# validate

Пакет `validate` решает задачу **единой валидации входных полей на границе сервиса**.
Каждый RPC перед работой обязан проверить формат входа — имя, описание, labels,
page-size, id ресурса — и вернуть понятную ошибку `INVALID_ARGUMENT`, если формат
нарушен. `validate` собирает эти проверки в одном месте: все сервисы валидируют одинаково
и возвращают одинаковые тексты. Каждый валидатор возвращает уже готовую gRPC-ошибку
(через [`errors`](/packages/errors)) — не булев флаг.

```go
if err := validate.NameVPC("name", req.GetName()); err != nil {
    return nil, err // InvalidArgument + BadRequest.FieldViolation
}
```

## Валидаторы

Все возвращают `error` (`nil` — если ок). Ни один не проверяет «is required» — пустоту
проверяет caller отдельно, чтобы сообщение было точным.

## Дисциплина resource-id и расширяемые префиксы

`ResourceID` принимает только id с **известным префиксом**. Базовый набор берётся из
[`ids.KnownPrefixes()`](/packages/ids); дополнительные префиксы (для доменов, чьи
константы живут в самом сервисе) добавляются через переменную окружения
`KACHO_EXTRA_RESOURCE_ID_PREFIXES` (константа `EnvExtraResourceIDPrefixes`). Так `ids`
остаётся единственным источником истины, а сервис при необходимости расширяет набор без
правки библиотеки.

```go
// malformed id → InvalidArgument первым стейтментом RPC
if err := validate.ResourceID("Network", ids.PrefixNetwork, req.GetId()); err != nil {
    return nil, err
}
```

## Update-mask дисциплина

`Update`-RPC принимает `google.protobuf.FieldMask`. `UpdateMask` реализует единое
правило: путь маски вне множества known-полей → `InvalidArgument`. Проверка immutable-
полей и full-object PATCH при пустой маске — на стороне use-case (по конвенциям Kachō),
а `validate.UpdateMask` закрывает именно «unknown path».

```go
known := map[string]struct{}{"name": {}, "description": {}, "labels": {}}
if err := validate.UpdateMask("update_mask", req.GetUpdateMask().GetPaths(), known); err != nil {
    return nil, err
}
```

## Корнер-кейсы и лучшие практики

- **Пустоту проверяйте отдельно.** Валидаторы имени пропускают пустую строку (кроме
  strict `Name`), потому что «required» — решение ресурса, а не формата.
- **`PageSize` возвращает нормализованное значение** — используйте его, а не исходный
  вход: `0` превращается в дефолт, слишком большое — в максимум.
- **Тексты стабильны** — они часть контракта (как в [`errors`](/packages/errors)). Регексы
  вынесены прямо в сообщение, чтобы клиент понимал требование без обращения к докам.
